# Moniq Gmail setup — local owner testing

This optional integration uses the backend OAuth authorization-code flow with PKCE S256, browser-bound one-time state, and the official Gmail API. Imported emails require review unless the local owner explicitly enables a trusted-sender SmartApprove policy and every conservative approval check passes. The existing synthetic demo is preserved. Private category corrections train a separate instance of the existing Moniq classifier. Public demo sessions cannot connect Gmail or access personal databases or tokens.

## Exact Google Cloud settings

Select your existing **Moniq-Test** project, ID **moniq-test-511217**. Gmail API, External audience, Testing mode, and your secondary account as a test user are already configured.

Under **Google Auth Platform → Clients → Create client**, enter:

| Setting | Value |
| --- | --- |
| Application type | **Web application** |
| Name | Moniq local backend |
| Authorized JavaScript origins | **Leave blank**; no frontend Google SDK or browser token exchange is used |
| Authorized redirect URI | **`http://127.0.0.1:8000/api/gmail/callback`** |
| Data Access scope | **`https://www.googleapis.com/auth/gmail.readonly`** |

The redirect is the implemented `GET /api/gmail/callback` route and the default `GMAIL_REDIRECT_URI` in `backend/app/config.py`. It is not a frontend route. The backend returns to **`http://127.0.0.1:5173/?gmail=connected#settings`** after authorization. Use **127.0.0.1** consistently; do not substitute localhost in one URL. Trailing slashes, paths, schemes, and ports must match exactly.

Google documents [web application OAuth clients and redirect matching](https://developers.google.com/identity/protocols/oauth2/web-server) and [Gmail scopes](https://developers.google.com/workspace/gmail/api/auth/scopes). Gmail read-only permits viewing email contents, but no sending, modification, or deletion. It is a restricted scope. Public distribution requires a separate authentication, HTTPS hosting, and Google review design; this integration is intentionally local owner testing. For an External app in Testing, Google normally gives these [refresh tokens a seven-day lifetime](https://developers.google.com/identity/protocols/oauth2); reconnect when it expires.

## Configure secrets locally

Run from PowerShell:

```powershell
cd D:\Map\Moniq
.\.venv\Scripts\python.exe -m pip install -r backend\requirements-lock.txt
.\.venv\Scripts\python.exe scripts\configure-gmail-key.py
notepad .env
```

The key script creates `.env` from `.env.example` if needed, generates a Fernet encryption key without printing it, preserves any existing key, and restricts its filesystem permissions. In **your local `.env` only**, fill the OAuth client values:

```dotenv
GMAIL_CLIENT_ID=your-web-client-id
GMAIL_CLIENT_SECRET=your-web-client-secret
# Keep the key generated by the script; never publish it.
GMAIL_TOKEN_ENCRYPTION_KEY=keep-the-generated-local-value
GMAIL_REDIRECT_URI=http://127.0.0.1:8000/api/gmail/callback
GMAIL_FRONTEND_URL=http://127.0.0.1:5173
PERSONAL_DATABASE_URL=sqlite:///./.runtime/personal.db
PERSONAL_MODEL_DIR=./.runtime/personal-models
GMAIL_TOKEN_DIR=./.runtime/gmail
```

Do not paste credentials into chat, Settings, frontend code, screenshots, or GitHub. `.env`, `.runtime`, SQLite databases, encrypted token files, downloaded credential JSON, models, and dependencies are Git-ignored. The client ID appears in the normal Google authorization URL; client secrets, access tokens, refresh tokens, and the encryption key stay on the backend. `credentials.enc` uses authenticated Fernet encryption and owner filesystem permissions; Windows grants the owner and SYSTEM access. Keep a private backup of the key. Losing it requires disconnecting and authorizing again; changing it does not decrypt old tokens.

## Start and test locally

Open two PowerShell terminals:

```powershell
# Terminal 1
cd D:\Map\Moniq
powershell -ExecutionPolicy Bypass -File .\scripts\start-backend.ps1
```

```powershell
# Terminal 2
cd D:\Map\Moniq
powershell -ExecutionPolicy Bypass -File .\scripts\start-frontend.ps1
```

The frontend script requires port 5173 and stops if it is occupied. Backend port is 8000. OAuth query strings are excluded from Uvicorn access logging by the backend script. Restart the backend after changing `.env`. Keep the backend bound to 127.0.0.1; it is a single-process local owner application, without production account authentication.

1. Open **http://127.0.0.1:5173**, then **Settings**.
2. Register a personal checking account: name, checking type, optional last four digits, **$10.00** starting balance, and the correct starting-balance date. This balance represents the amount **before that date's transactions**. Do not enter a current balance that already includes emails you plan to confirm.
3. Click **Open personal workspace**. The dashboard now uses the separate personal database. The original `.runtime/moniq.db` and its demo history remain available through **Use synthetic demo**.
4. Click **Connect Gmail**, choose your secondary Gmail test user, and authorize Gmail read-only access for your own Google project. A successful callback returns to Settings.
5. Click **Sync Now**. It searches supported financial terms in the last 30 days, excluding spam/trash, with a maximum of 250 messages per click. If more remain, another Sync Now continues the saved cursor. No balance changes happen during sync.
6. Review each email's merchant, USD amount, posted date, account suffix, ML category/confidence, and warnings. Select the registered account; correct any ambiguity. Verify the actual bank posting and check **I verified this is posted...**, then **Confirm email transaction**. Dismiss marketing, pending, failed, duplicate, or future-bill notices.
7. For a confirmed **$400 paycheck** assigned to checking, the balance becomes **$410**. Confirm a **$15 checking purchase**, and it becomes **$395**. Dashboard, budget spending, forecasts, and the existing grounded assistant use those same stored records. Other account balances are shown individually in Settings; the dashboard combines their signed balances, including debt.
8. **Disconnect Gmail** revokes Google authorization and removes local tokens; confirmed records remain. If Google revocation fails, remove Moniq under your Google Account's connected-app permissions too. **Delete all data** in the personal workspace disconnects and deletes that workspace's financial records. Reset Demo is blocked in personal mode.

Gmail has no polling timer or background push subscription in this version; Sync Now is user initiated. Financial emails may omit account digits or include several amounts/dates. Unsupported currencies, uncertain deposits, bill notices, missing merchant fields, and uncertain ML predictions need manual review. Missing or conflicting last four digits never select an account automatically. Earlier-than-starting-balance and future transactions cannot be confirmed. Credit-card purchases belong to the credit account, not checking; bank/card transfer reconciliation is outside this importer.

The importer stores extracted review fields and message IDs, not full email bodies or attachments. HTML is reduced to visible text without fetching images or links. Gmail message IDs are namespaced by mailbox; reconnecting does not duplicate reviewed messages. Account/date/merchant/signed-amount deduplication also prevents cross-email duplicates, with the existing limitation that truly identical same-day purchases can need distinct merchant labels.

## Troubleshooting and checks

- **redirect_uri_mismatch:** compare the Google client redirect with the backend's `/api/gmail/status` `redirect_uri`; default is exactly the URI above. Restart after `.env` changes.
- **Connect Gmail disabled:** all three credential/key variables must be present. Generate a valid key, add your OAuth client ID/secret, and restart. Do not put them in `VITE_...` variables.
- **access_denied or test user restriction:** use the secondary account registered under Audience → Test users for this same Google project and verify Gmail API/Data Access.
- **Invalid/wrong-browser/expired state:** start Connect Gmail again in the same browser. State is single use and expires after ten minutes or a backend restart.
- **Refresh expired/revoked:** reconnect. External Testing commonly expires refresh authorization after seven days.
- **Cannot decrypt tokens:** restore the original key or click Disconnect Gmail to remove the unreadable local store, then reconnect. Confirmed transactions stay intact.
- **Quota/API error:** retry later. A failed Gmail read does not confirm transactions or change balances.

## Final account and dashboard controls

Pending review items are available directly on Overview in the personal workspace. Connection, sync, disconnect and account configuration stay in Settings. Checking/savings cash is separated from credit debt. Debit-card aliases route matching suffixes to their linked checking account. Internal transfers/card payments are entered as one paired movement and manual reconciliation preserves history through an adjustment. Do not import a transfer a second time as income or a purchase.

For recording servers only, `MONIQ_GMAIL_DISABLED=true` prevents loading OAuth IDs/secrets/key into the Gmail configuration even if a local `.env` exists. Use different DATABASE_URL, PERSONAL_DATABASE_URL, SCENARIO_DATABASE_URL, model paths and GMAIL_TOKEN_DIR as documented in DEMO_SCRIPT.md. The normal owner server leaves this flag false; the existing credentials and encryption key remain unchanged. No Google credentials are included in media or submission archives.
